# Chandamama blocks (closed vocabulary)

The `{...}` blocks of Chandamama ideal Markdown: form and meaning. The linter rejects anything else.

- `{pb}` — para-break witness, bare, closing every asserted break in both single and double column modes (column turns mid-section, page turns at section end). A following `{pc}` means the paragraph continues across the break (spaced join); a fresh opening — indented new paragraph, title, or story break — means a clean paragraph break at the edge. Only `{...}` blocks or whitespace may follow it inside the paragraph, never bare text. E.g. `कुत्र{pb}` continuing as `{pc}गच्छति इति अहं तु न जानामि।`; `दत्तवान्।{pb}` clean break.
- `{pgb}` / `{pgb: १३}` — page-end marker, always the last token of the page section, after footers (`...{pb}{pgb: ८}`, `{author: श्वेता}{pgb}`). The value is the printed folio in Devanagari numerals where visible, else bare `{pgb}`. It says *this page ends here*; `{pb}` says *what the paragraph does here*. Never mid-section.
- `{pc}` — para continuation, bare, opening the first body paragraph of a page or column whose text continues the previous page or column; pairs with that page's `{pb}` or `{wb}`, or the previous column's `{pb}` or `{wb}`. The print decides: straight continuation with no indent takes `{pc}`; an indented new paragraph, a title, or a story break takes none. E.g. `{pc}दयतः पूर्वमेव...`, `{pc}राजा भवतु।`.
- `{wb}` — word-break cut inside a word: `{wb}` marks the solid join, `{pb}` the spaced join, and Sanskrit decides which — a continued word takes `{wb}`, anything else takes `{pb}`. `{wb}{pc}` joins with no space, `{pb}{pc}` with one space. A genuinely undecidable join takes `{pb}` plus `{x-com: join ambiguous: space or solid?}`. The print hyphenation mark is dropped on the join. E.g. `सूर्यो{wb}` continuing as `{pc}दयतः` in the next column/page. Glued compounds keep the `-`. E.g. `राम-{wb}{pc}राज्य-संस्थापनम्`.
- `{author:}` / `{note:}` / `{category:}` / `{misc:}` — footer metadata: bylines to `{author:}`, reprint lines to `{note:}`, story labels to `{category:}`, anything else to `{misc:}`. Node contents are proofread like body text. The magazine name in any spacing is never transcribed. E.g. `{author: विवेकः}`, `{note: पञ्चविंशति-वर्षेभ्यः पूर्वं चन्दमामायां प्रकाशिता कथा।}`, `{category: चीनादेशिया जानपदकथा}`.
- `{x-missing:}` / `{x-illegible:}` — source absent / unreadable, no reading offered: missing when the source itself is gone, illegible when present but unreadable even enlarged. A wholly lost page is a page section containing only the block. Dropped with log. E.g. `{x-missing: page 13 absent from scan}`, `{x-illegible: glyph illegible at 3x}`.
- `{x-com:}` — note to the user; never compiled, never applied. Content stays clean prose although tools ignore it for quotes and Latin. E.g. `{x-com: gutter shadow on this line, verify}`, `{x-com: join ambiguous: space or solid?}`.
- `{del:}` / `{ins:}` — verified deletion and insertion verdicts, span first: the block names the print span, the replacement follows it. Applied. E.g. `{del:घुटिकां}{ins:गुटिकां}`; lone `{ins:'}` for a dropped inner close with certain position; lone `{del:"}` for a stray mark.
- `{sug-del:}` / `{sug-ins:}` — unverified deletion / insertion candidates in the same span-first shape. A lone `{sug-ins:}` marks a pure insertion with no print span; a lone `{sug-del:}` a pure deletion with no replacement (`रामभद्रः {sug-del:रामभद्रः}`). Held, never applied. E.g. `{sug-ins:यदा सोमः}` for a missing word; `{sug-del:अगायतः}{sug-ins:अज्ञातः}` as a reading guess. Sides pair del-first (the linter requires `{del:}`/`{sug-del:}` before `{ins:}`/`{sug-ins:}`) so each side carries its own confidence: `{del:घुटिकां}{sug-ins:गुटिकां}` (removal certain, replacement candidate), `{sug-del:घुटिकां}{ins:गुटिकां}` (insertion certain, removal candidate); both-uncertain goes `{sug-del:अगायतः}{sug-ins:अज्ञातः}{x-com: print unclear at 3x}` plus a report note. Every block keeps a non-empty value; bare `{sug-ins:}`/`{sug-del:}`/`{x-com:}` is rejected.

## Usage

- Transcriber emits `{sug-del:}`/`{sug-ins:}` instead of `{del:}/{ins:}`. Proofreader can promote the unverified `{sug-del:}`/`{sug-ins:}` to verified versions, or drop them altogether, after examining the context/scan.
- Proofreader can emit its own `{sug-del:}`/`{sug-ins:}` (e.g. `{sug-ins:यदा सोमः} उपहासवचनानि शृणोति तदा बहु खिन्नः भवति।`) if the context requires it.
- Transcriber emits the structural, `x-`, author/note/category/misc blocks. Proofreader should proofread the node contents, but otherwise leave them alone. And it may emit the x-com version if it wants to provide the user with additional commentary.
- Transcriber declares each page's art/column layout before reading it, archived as one standalone `{x-com:layout: …}` chunk per page section of the story file (e.g. `{x-com:layout: 2col, art top-right}`; the `layout:` prefix keeps it greppable — see `1984_04/p01.extract.md`), and marks every asserted break with bare `{pb}` (a same-section `{pb}` is a column turn; a section-final `{pb}` plus `{pgb}` is a page turn).
